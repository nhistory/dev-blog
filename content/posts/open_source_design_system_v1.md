### React와 Panda CSS를 선택하기까지

- 인트로

  - DaleUI 디자인 시스템 프로젝트 소개 (한글 사용자를 위한 오픈소스 디자인 시스템 목표)
  - 기존 디자인 시스템이 있음에도 새로운 시스템을 만드는 이유 (DaleUI만의 차별점 또는 필요성)
  - 디자인 시스템의 성공을 좌우하는 기술 스택 선택의 중요성
  - 이 글 (1부)에서는 코어 프레임워크와 스타일링 솔루션이라는 가장 근본적인 기술 결정 과정을 다룰 것을 예고

- 첫 번째 갈림길: 웹 컴포넌트 vs. React

  - 초기 고려: 웹 컴포넌트 (Web Components)
    - 왜 웹 컴포넌트를 먼저 고려했는가? (프레임워크 독립성, 표준 기술, 장기적인 관점)
    - 고려 과정에서 느낀 웹 컴포넌트의 장단점 (장점: 호환성 / 단점: 개발 생태계, DX 등)
  - 방향 전환: React 도입 결정
    - 웹 컴포넌트 대신 React를 사용하기로 결정한 이유 (개발 생산성, 풍부한 생태계, 팀의 경험, 커뮤니티 지원)

- 코어 결정: React + TypeScript

  - 왜 React인가?
    - 여러 프레임워크 (Vue, Svelte 등) 중에서 React를 선택한 이유 (컴포넌트 기반 아키텍처, 방대한 생태계, 자료의 풍부함, 상대적 익숙함 등)
  - 개발 효율과 안정성 강화: TypeScript 도입
    - JavaScript 대신 TypeScript를 선택한 이유 (정적 타입 체크의 이점, 코드 가독성 및 유지보수성 향상, 대규모 프로젝트 관리 용이성)
    - React + TypeScript 조합이 DaleUI 개발에 가져다 줄 기대효과

- 핵심 과제: 최적의 스타일링 솔루션 찾기

  - 명확한 목표 설정: 빌드 타임 스타일링 우선
    - 디자인 시스템에서 스타일링이 왜 중요한가? (일관성, 성능, 유지보수)
    - 초기부터 런타임 CSS-in-JS (예: MUI, Chakra UI의 기본 방식)를 배제한 이유 (성능 오버헤드 우려, 번들 사이즈 증가, 예측 가능성 등)
    - 빌드 타임에 스타일을 생성하는 방식의 장점 강조 (제로 런타임, 정적 CSS 추출, 성능)
  - 빌드 타임 솔루션 비교: Panda CSS vs StyleX
    - 고려했던 주요 빌드 타임 스타일링 솔루션 소개 (Panda CSS, StyleX 등)
    - StyleX (Meta): 컴포넌트 중심의 스타일링과 예측 가능한 스타일 충돌 방지
    - Panda CSS: 유틸리티 기반 워크플로우를 제공하며, 개발자가 자유롭게 스타일을 조합할 수 있도록 설계
  - 최종 선택: Panda CSS
    - DaleUI가 Panda CSS를 선택한 결정적인 이유 (타입 안전성, 개발 경험, 설정 유연성, 디자인 토큰 관리 용이성 등 DaleUI의 지향점과 부합)
    - Panda CSS 도입으로 기대하는 효과

- 1부 마무리
  - 지금까지 결정된 핵심 기술 스택 (React, TypeScript, Panda CSS) 요약
  - 이러한 결정이 DaleUI의 기반을 어떻게 형성하는지 강조
  - 다음 2부에서는 이 기반 위에 컴포넌트 개발, 문서화, 테스트, 빌드 등을 위한 지원 도구와 생태계를 어떻게 구성했는지 이야기할 것을 예고하며 마무리. (2부 링크 포함)
